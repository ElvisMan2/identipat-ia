# Handoff frontend — F1.4E

No hay endpoints nuevos. Angular sigue comunicándose únicamente con Java.

## Resultado canónico

`GET /analyses/{analysisId}` devuelve para análisis nuevos:

```json
{
  "status": "COMPLETED",
  "result": {
    "schemaVersion": "analysis-result/3.0",
    "summary": "Resumen orientativo.",
    "protectionOptions": [],
    "patentScreening": {
      "applicable": false,
      "article15": {"assessment":"NO_POTENTIAL_MATCH","rationale":"Sin indicios.","matches":[]},
      "article20": {"assessment":"NO_POTENTIAL_MATCH","rationale":"Sin indicios.","matches":[]}
    },
    "geneticResourceAccess": {
      "assessment": "NOT_INDICATED",
      "rationale": "Sin indicios.",
      "missingInformation": []
    },
    "traditionalKnowledgeAccess": {
      "assessment": "POTENTIALLY_REQUIRED",
      "rationale": "Existen indicios que requieren revisión bajo la Ley N.º 27811.",
      "missingInformation": ["Finalidad exacta de utilización"]
    },
    "observations": [],
    "warnings": []
  }
}
```

`traditionalKnowledgeAccess` siempre existe en el resultado V3. Estados:

- `POTENTIALLY_REQUIRED`: mostrar “Requiere revisión especializada”.
- `INSUFFICIENT_INFORMATION`: mostrar “Se necesita más información” y la lista no vacía.
- `NOT_INDICATED`: no mostrar una alerta; `missingInformation` es `[]`.

## Reporte

`GET /analyses/{analysisId}/report` añade, al mismo nivel que `geneticResourceAccess`:

```json
{
  "traditionalKnowledgeAccess": {
    "assessment": "POTENTIALLY_REQUIRED",
    "assessmentLabel": "Requiere revisión especializada",
    "rationale": "Texto canónico presentado.",
    "missingInformation": ["Finalidad exacta de utilización"]
  }
}
```

La propiedad se omite para V1/V2 y para V3 `NOT_INDICATED`. El título visual es “Acceso a
conocimientos colectivos de pueblos indígenas” y la referencia general es Ley N.º 27811. No duplique
esta alerta desde `warnings` ni la convierta en modalidad.

Los análisis nuevos V3 devuelven `reportVersion: diagnostic-report/1.1`. Los reportes V1/V2 y los
contextos históricos conservan `diagnostic-report/1.0`. La migración V14 permite ambas versiones y
la descarga JSON/PDF lee la versión guardada junto con el disclaimer histórico. Las URLs, sesión
STANDARD, JWT ADMIN y disclaimer no cambian.
